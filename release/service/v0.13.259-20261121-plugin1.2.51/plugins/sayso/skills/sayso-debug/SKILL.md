# SaySo 调试报告

先调用 `get_debug_report` 获取服务器报告。默认最近 15 分钟、最多 20 条；用户指定范围时使用 `minutes`（1–60）和 `limit`（1–50）。多设备返回 CHOOSE_DEVICE 时，用当前对话已确定的设备 ID；无法确定时请用户选择设备，再传 `device_id`。不要通过看屏、点击、重试原操作或更改许可来生成报告。

服务器结果的 `report` 是完整 Markdown，包含【环境】【当前状态】【最近操作】【最近状态变化】【汇总】，时间为 SGT 毫秒。逐字段原样输出，不总结、不猜原因、不省略字段、不改写服务器错误码或未知值。工具拒绝或失败时原样保留返回的请求 ID、错误码，说明服务器报告未取得；不要编造完整报告。

取得服务器部分后，按本次可见对话补上以下一节，再输出整份报告。把本节放在服务器报告之前，服务器 `report` 内容保持原样。

【这次对话的经过】

| # | 用户的指令（简述） | ChatGPT 调用的操作（按顺序） | 请求 ID | 结果 / 错误码 | 第几次尝试 |
|---|---|---|---|---|---|

- 每条用户指令占一行；实际工具调用按顺序列出，用 `→` 连接。多次调用的请求 ID、结果和尝试序号按相同顺序用 `/` 对齐，保留完整 ID。
- 请求 ID 只从每次真实工具返回的 `mcp_request_id`（或请求元数据 `sayso_performance.request_id`）提取，与服务器最近操作逐条核对；对话中有、服务器窗口内没有的调用标“服务器记录不可用”。缺失 ID、不可见的历史或无法核对的次数写“未知”，不猜造。
- “第几次尝试”优先对应服务器同工具、同目标 60 秒内的序号；对话自有重试要另行明确标注。每行之后写明“本指令共调用 N 次；重试：第 … 次／无／未知；最终：完成／失败／已放弃／未放弃／未知”，仅据实际对话判断。
- 用户指令只写安全简述；输入文字用“输入文字”代替，不复述具体文字。删除密码、卡号、账号邮箱、地址等私人资料以及令牌、proof、签名、密钥、门禁资料。不要加入截图、图片、图片链接、编码数据或工具参数。只保留操作名、请求 ID、结果和次数等调试事实。
- 这段对话经过只出现在回复里，不调用任何工具保存或上传，不传给服务器。服务器汇总涵盖其现存时间窗口，可能包含其他对话；不要把它当成本次对话的调用总数。
- 本次无历史操作时保留表头，写“（本次对话无可用操作记录）”。

语音模式仍将完整报告放进对话，口头只说一句：“调试报告已经放在对话里了，可以直接复制”。不要朗读表格或报告。文字模式直接输出整份报告。
